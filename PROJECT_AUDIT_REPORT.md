# PATHFORGE Forensic Audit Report

## 1. Executive Summary
This audit investigated the severe performance drop in the PATHFORGE career recommendation system, identifying why the fresh evaluation yielded a Top-1 accuracy of **5.33%** compared to the historically reported **65.0%**. The investigation revealed two critical failures:
1. **A structural schema mismatch** in the fresh evaluation pipeline (`run_fresh_inference.ts`) caused the Assessment score to permanently evaluate to 0 for all classes.
2. **A fatal mathematical independence flaw** in the fresh synthetic dataset generator (`generate_dataset.py`). The generator assigns ground-truth careers and student skills using independent, uncorrelated random matrices (`W_c` and `M_Skill`). Consequently, the generated synthetic profiles have absolutely zero semantic alignment with their assigned "true" career.
3. The previously reported 65.0% accuracy was evaluated on an older dataset (`student_dataset_500_development.csv`) that suffered from circular target-conditioned generation (features were explicitly injected with the ground-truth label).

As a result, the current heuristic recommendation engine (which expects realistic semantic correlations) performs at random-chance levels (5.33% vs uniform random 6.67%).

## 2. Current System Architecture
The recommendation system uses a rule-based heuristic engine:
- **Profile Evaluation (`RecommendationEngineService`)**: Evaluates a student's profile across 7 dynamically weighted dimensions (Skills [35%], Interests [20%], Projects [15%], Academics [10%], Certifications [10%], Coding [5%], Goals [5%]).
- **Assessment Evaluation (`run_fresh_inference.ts`)**: Iterates through 20 Likert-scale questions, applying predefined static weights from `career_assessment_questions_v1.json` to score 15 career classes.
- **Fusion Engine**: Linearly combines the Profile (70%) and Assessment (30%) scores, sorting the final aggregate to produce the Top-K recommendations.

## 3. Current Recommendation Mathematics
Formally, for a given student $S$ and career $C$:

$$ Score_{profile}(C) = \sum_{i \in F} (w_{i} \times Score_{i}(S, C)) $$
Where $F$ = {Skills, Interests, Projects, Academics, Certifications, Coding, Goals} and $w_i$ is dynamically adjusted based on `yearStage`.

$$ Score_{assessment}(C) = \frac{\sum_{q=1}^{20} (\text{if matched: } weight(q, C))}{MaxPossibleScore} \times 100 $$

$$ Score_{final}(C) = 0.70 \times Score_{profile}(C) + 0.30 \times Score_{assessment}(C) $$

## 4. Current Data Pipeline
The current evaluation pipeline uses a randomly generated synthetic dataset of 2,000 samples created via `generate_dataset.py` located in `research/fresh_evaluation/`. 
Data flows from JSON definition to `run_fresh_inference.ts`, which reconstructs profiles, queries the `CareerKnowledgeService` for career definitions, evaluates each profile, and calculates ablations by passing zeroes for specified weights.

## 5. Synthetic Ground-Truth Generation
The fatal flaw exists in the mathematical construction of the dataset.
- A latent student vector $LV \sim \mathcal{N}(0, 1)$ of dimension 20 is generated.
- **True Career ($S_c$)** is determined by: $S_c = LV \cdot W_c^T + \text{noise}$, where $W_c$ is a completely random weight matrix.
- **Skills ($skill\_logits$)** are generated by: $skill\_logits = LV \cdot M_{Skill}^T$, where $M_{Skill}$ is **another completely independent** random matrix.

**Mismatch:** Because $W_c$ and $M_{Skill}$ are independent, the latent projection completely severs any real-world correlation. A student whose "true career" is generated as *Data Scientist* might be randomly assigned skills in *C#* and *.NET* because the semantic mappings are ignored.

## 6. Evaluation Pipeline
The `run_fresh_inference.ts` script iterates over the 2,000 samples, calculating profile, assessment, and fusion scores. The resulting predictions are saved to `06_test_predictions.json` and passed to `compute_metrics.py`. 
`compute_metrics.py` implements Top-1, Top-3, Top-5, MRR, and NDCG@5 by sorting the returned scores and comparing the Top-K array to the ground-truth string.

## 7. 5.33% Accuracy Investigation
The 5.33% accuracy is effectively equivalent to a random guess (1/15 = 6.67%).
1. **Assessment Collapse:** A bug in `run_fresh_inference.ts` queries for `q.id === "Q1"` while the JSON schema contains `question_id: "Q01"`. It also queries `qDef.options` which does not exist. As a result, the assessment score for every career is exactly 0.
2. **Profile Randomness:** Because the synthetic student's skills and their synthetic "true career" are mathematically uncorrelated, the profile-scoring algorithm (which uses real semantic rules) is effectively predicting on random noise.

## 8. 65% vs 5.33% Discrepancy

| Dimension | Old Paper Experiment | New Experiment | Difference | Impact |
| --- | --- | --- | --- | --- |
| **Ground-Truth Data** | `student_dataset_500` | `dataset_...csv` | Synthetic Generation | Old dataset explicitly embedded the target label into the features |
| **Leakage / Circularity**| High (Target-Conditioned) | None (Independent) | Circularity removed | Accuracy collapsed from 65% to random chance |

**Conclusion:** Both results are "correct" mathematically. The old 65% was the result of a heavily biased, circular synthetic dataset where the answers were hard-coded to match the ground truth. The new 5.33% is the result of a perfectly uncorrelated synthetic dataset. The 65% paper result is highly susceptible to reviewer critique due to target leakage.

## 9. Baseline Analysis
- **Uniform Random Top-1:** 1/15 = 6.67%
- **Uniform Random Top-3:** 3/15 = 20.00%
- **Uniform Random Top-5:** 5/15 = 33.33%
- **Majority Class Top-1:** ~7-10% (slight generator bias)
*The current model (5.33%) is underperforming the uniform random baseline, confirming structural noise.*

## 10. Ablation Analysis
The current ablation results (e.g., removing Skills vs removing Projects) are identical (5.33%) because the features themselves contain no mutual information with the target class. Removing Certifications or Goals artificially increased Top-1 (to 5.77% and 6.55%) simply due to statistical variance when dealing with random permutations. 
The static weights (`BYSER_WEIGHTS`) cannot be validated or tuned on the current dataset.

## 11. Error Analysis
Errors are categorically identical across the board: **Label-Generation Mismatch**.
A synthetic student might perfectly match the `CareerKnowledgeService` definition of a *Frontend Developer* based on their generated skills (React, HTML), but the random projection matrices ($W_c$ and $M_{Skill}$) assigned their ground truth as *Cybersecurity Engineer*. The recommender is punished for making the semantically correct choice.

## 12. Data/Label Quality Issues
- **CRITICAL:** Missing semantic mapping in `generate_dataset.py`. Ground truth relies on $W_c$, which is purely random.
- **CRITICAL:** Schema mismatch in `run_fresh_inference.ts`. `q.id` vs `q.question_id` completely neutralizes the Assessment module.

## 13. Critical Bugs or Risks
1. **`run_fresh_inference.ts:38`** - `qId: "Q${q}"` must be `qId: "Q${q.toString().padStart(2, '0')}"`.
2. **`run_fresh_inference.ts:43/53`** - `qDef?.options` does not exist. The script must directly map `userAnswers[i].value` via `career_weights` scaled by Likert responses.
3. The dataset generation script `generate_dataset.py` mathematically invalidates any heuristic or machine learning validation attempt.

## 14. Recommended Improvements
Before upgrading any ML model, the fundamental data correlation must be established.
1. **Semantic Ground-Truth Assignment (High Priority, Low Complexity):** Modify `generate_dataset.py` so that a student's "true career" is assigned by running the actual `RecommendationEngineService` against the generated profile, adding realistic noise (label flipping).
2. **Bug Fixes (High Priority, Low Complexity):** Fix `run_fresh_inference.ts` JSON schema parsing.
3. **Adaptive Feature Weighting (Medium Priority, Medium Complexity):** Implement LightGBM or XGBoost on top of the 7 profile factor scores to dynamically tune `BYSER_WEIGHTS`.

## 15. Proposed Research Architecture
**Hybrid Semantic-LTR (Learning-to-Rank) Architecture:**
- **Layer 1 (Semantic Base):** Retain the current heuristic engine to extract 7 semantic factor scores + 1 Assessment score.
- **Layer 2 (ML Ranker):** Use an XGBoost Ranker (pairwise or listwise) trained on the 8 scalar outputs to learn the optimal fusion and feature weights dynamically, rather than relying on hard-coded 70:30 splits.

## 16. Experimental Design
1. **Data Fix:** Regenerate the dataset where the ground truth is semantically aligned (using domain-expert mappings or the heuristic engine itself as the base signal).
2. **Splits:** 70% Train, 15% Val, 15% Test.
3. **Model:** Train the XGBoost Ranker on the Train set.
4. **Baselines:** 
   - Random Guessing
   - Current Heuristic Engine (Static 70:30)
5. **Metrics:** Top-1, Top-3, Top-5, NDCG@5, MRR.
6. **Significance:** Wilcoxon signed-rank test to prove the ML Ranker significantly outperforms the static heuristic.

## 17. Expected Evaluation Strategy
Validate the new Hybrid ML system strictly against the semantically-aligned synthetic dataset. Explicitly document in the research paper how the synthetic data was created (emphasizing that skills map logically to careers) to defend against the circular-generation critique present in the old paper.

## 19. Limitations
Synthetic data, even when generated with semantic alignment, inherently limits external validity. The performance of the heuristic engine on synthetic data generated *by* the heuristic engine will be artificially high. The ML ranker is mostly learning to denoise the injected randomness.

## 20. Exact Next Steps

2. **Rewrite `generate_dataset.py`** to use the `RecommendationEngineService` as the ground-truth oracle (plus Gaussian noise) OR map the latent dimensions using explicit real-world correlation matrices rather than random $W_c$.
3. **Rerun inference** and compute baseline accuracy.
4. **Implement XGBoost Ranker** on the extracted scores.
