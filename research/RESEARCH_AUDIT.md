# PATHFORGE - Complete Research Audit Report

## A. What the system actually implements
1. **Deterministic Scoring Engine**: A heuristic rule-based recommender (`RecommendationEngineService`) that calculates weighted scores for skills, interests, academics, projects, certifications, coding, and goals.
2. **Assessment Fusion**: A component (`CombinedRecommendationService`) that merges the profile heuristic score with a questionnaire assessment score (defaulting to a 70:30 fusion weight).
3. **Roadmap Generator**: A prerequisite-aware learning roadmap builder (`RoadmapEngineService`) that determines skill gaps, resolves dependencies using a topological sort on a skill graph, and stages learning materials sequentially.
4. **Market Demand (Stubs)**: The code for market demand injection exists as commented-out code (`// FUTURE: Inject market demand context here`) in the core engine.

## B. What the paper claims
1. A dynamic weighted network driven by **Acyclic Market Topologies**.
2. Integration of semantic taxonomy matching with statistical labor market vectors ($M_t$).
3. Performance over heavily perturbed **Bayesian user profiles**.
4. The proposed B1 modification shifts to **Demand-based Optimization**.
5. Constraint violations in learning pathways dropped to **absolute zero**.

## C. Which claims are experimentally supported
1. **Zero Constraint Violations**: The roadmap engine successfully utilizes topological sorting to ensure prerequisites are met before advanced skills, resulting in 0% dependency violations.
2. **Deterministic Recommendation Engine**: The top-K accuracy (Hit@5 = 85.4%) demonstrates the scoring logic works effectively on the synthetic dataset, when leakage is patched.
3. **Computational Efficiency**: The heuristic nature of the engine is extremely fast per student profile inference.

## D. Which claims are unsupported
1. **Market Demand Optimization**: The paper heavily emphasizes a demand engine ($M_t$) and market-aware constraint planning, yet the actual recommendation engine has this feature commented out. The engine currently does not adapt dynamically to market flux.
2. **Bayesian User Profiles**: The dataset consists of 500 uniformly synthetic student profiles generated via heuristic rules, not true Bayesian matrix sampling.
3. **70:30 Fusion Performance**: The quantitative evaluation (Top-1, Top-5 metrics) currently reports on the profile recommendation engine, completely ignoring the 70:30 assessment fusion logic.
4. **Learning Outcomes**: The paper implies the roadmaps create valid learning trajectories, but this has only been structurally verified, not pedagogically verified with human subjects.

## E. Data Leakage Risks
1. **Target Role Leakage**: As identified in the leakage audit, passing `career_preference` into the `student.careerGoals.targetRole` object guarantees a +100 Goal Score for the exact label being predicted. This must be masked out during rigorous ML baseline and heuristic evaluation.
2. **Synthetic Feature Correlation**: Because the dataset is synthetic, the `skills` array was generated *from* the `career_preference`. Any ML model trained on this will essentially learn to reverse-engineer the generation script.

## F. Evaluation Flaws
1. **Weak Baseline**: The current report compares the heuristic engine against a "Random baseline". An IEEE paper requires comparison against standard TF-IDF/cosine similarity, Logistic Regression, or Random Forest models.
2. **Synthetic Data**: Evaluating a heuristic recommendation engine on a synthetic dataset generated by similar heuristics results in circular validation. 
3. **Missing Assessment Validation**: The 70:30 Assessment Fusion component is omitted from the main evaluation pipeline.

## G. Reproducibility Problems
1. The evaluation scripts rely on in-memory Node.js services and hardcoded JSON/CSV paths rather than a standardized ML experiment pipeline.
2. A single script (`run_all_experiments.py` or equivalent) that automatically parses data, trains baselines, runs the heuristic, and outputs a formatted table is missing. 

## H. Software Bugs Affecting Scientific Validity
1. The missing market demand implementation fundamentally invalidates the paper's core title and abstract claims.
2. The dataset has "ontology overlap" (Frontend vs Full Stack Developer), causing 0% Hit@5 for Full Stack Developer, showing the taxonomy vectors are flawed or perfectly overlapping.

## I. Missing Experiments
1. **Standard ML Baselines**: Majority-class, TF-IDF, Logistic Regression, Random Forest, XGBoost.
2. **Fusion Sensitivity Analysis**: Testing 100:0, 90:10, ..., 0:100 to justify the 70:30 parameter.
3. **Human Validation / Real-world dataset**: At least 100-300 real student profiles.
4. **Roadmap Expert Evaluation**: Human/expert Likert scale ratings on the generated roadmaps.

## J. Paper-Writing Problems
1. **Word-Salad Jargon**: Terms like "Bayesian Matrix profiles" and "Acyclic Market Topologies" are used to dress up standard synthetic data and DAG topological sorting. This will immediately trigger reviewer suspicion.
2. **Conversational/Meta wording**: Though I need to audit the `.tex` file fully, the user mentions conversational tone exists ("I think", "I see").
3. **Unimplemented Features Claimed**: Section 3 (Methodology) discusses Data Normalization and Demand Engine which are not actively modifying the ranks in the actual source code.

## K. Likely Reviewer Objections
1. **Reviewer A (Methodology)**: "The paper claims a Market-Demand Optimization vector, but I see no experiment ablating the market demand vector vs a non-market demand vector. Furthermore, a random baseline is unacceptable for a recommendation systems paper."
2. **Reviewer B (EdTech)**: "Generating roadmaps with zero topological cycles is a basic graph algorithm constraint, not a pedagogical evaluation. Does this roadmap actually help a student learn faster?"
3. **Reviewer C (General)**: "The dataset is purely synthetic. The 85% Hit rate merely demonstrates the heuristic rules map back to the generation script. The paper uses highly inflated terminology (Bayesian Matrix profiles) for basic concepts."
